## Wave 2: bilingual publication and truthful topic counts

After wave 1 integration, freeze a new exact base and `october-issues/v2` before
dispatch. #3 and #10 share the web read owner. A pipeline owner implements the
canonical English summaries, Turkish translation, additive schema migration and
atomic publication. A web owner implements matching-language projection, language
switch behavior, run confirmation and #3. Neither owns the other's files; shared
pricing/accounting/quality seams are assigned explicitly in the v2 revision.

The intended data contract is one canonical English bulletin with one set of
items, reusable Turkish summary translations, translated editor note and item
reasons. Translation failure prevents a new bulletin and preserves the previous
publication. Legacy bulletins retain their original stored content. Tags, source
names and URLs remain identifiers. Translation uses the selected summary model.
The pipeline contract includes a conservative translation cost estimate, reuse of
completed translations on retry and visible costs for failed paid work.

## Worker completion and integration

Workers use `parallel-lane-runner`, commit only owned paths and return STATUS,
LANE, BASE_SHA, COMMIT_SHA, CONTRACT, CHANGED_FILES, CHECKS_RUN, ASSUMPTIONS,
KNOWN_GAPS and INTEGRATION_NOTES. They do not push, merge, delete worktrees or
close issues. The coordinator is the single integration writer and uses
`integration-gate` after at least two completed reports.

Reversible choices are recorded and implemented. Escalate a scope expansion,
destructive data change, credential exposure, unstable contract or untrusted oracle.
GitHub delivery and initial CURRENT_STATE creation follow the owner's answers.
An issue closes only with reviewed executable evidence and the corresponding
delivered commit/PR. Subjective design gates are never inferred from test results.
